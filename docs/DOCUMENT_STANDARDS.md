# 文档规范（DOCUMENT_STANDARDS）

> 本仓库是游戏设计文档库。所有 docs/ 下文档必须遵守以下标准（code-review 的 Standards 轴依据；仓库未覆盖之处适用通用"坏味道"基线：含糊命名/重复内容/占位符滥用/悬空引用等，均为判断性提示而非硬性违规，仓库明示标准优先）。

## 硬性标准

1. **版本与状态**：每份主文档头部必须有版本号、日期、状态三件套；修订必须递增版本并在文末说明变更来源。
2. **可溯源**：引用逆向事实必须指向来源文件或附录映射表；引用本仓库其他文档用相对路径；外部结论标注"初检/待复核"。
3. **数值完整性**：任何机制描述若含数值，必须带单位与公式（公式含守卫：clamp/max/除零防护）；禁止无单位的裸数字进入正文表格。
4. **交叉引用格式**：统一 `§N.M` 格式；重编号后必须全文回归（引用目标必须真实存在且内容匹配）。
5. **密钥纪律**：任何文档不得出现真实 API Key/密钥（只能有占位符）；密钥只能存于 gitignore 的本地配置（config/secrets.local.json）。
6. **决策闭环**：标记"待决策（Q#）"的问题必须有编号且集中登记；已决策项必须同步关闭相关 Q 编号并在正文落定。
7. **商业化一致性**：全免费定位下，不得残留任何收费/订阅/内购表述（含"建议收费"措辞）。
8. **术语一致**：同一概念全文用同一称呼（本项目：智能体在叙事/UI 层统一称"系统"，机制层可并用"系统（军师）"）；改名后旧称不得在新章节正文出现（历史章节/审查记录除外）。
9. **表格规范**：表格列含数值时表头注明单位；对照表必须给出处。
10. **合规红线**：涉及 LLM/云调用必须包含数据流向声明与"Coding Plan 白名单限制"提示；涉及第三方素材必须带许可证。

## 判断性基线（软标准）

- 悬空引用（指向不存在的章节/文件）视为缺陷。
- 同一规则在两处描述不一致视为缺陷（即使都能自圆其说）。
- "待补/TODO"超过 5 处视为文档不完整。
- 继承自旧版的机制描述与新框架冲突时（如收费残留、旧叙事残留），视为迁移不彻底。
