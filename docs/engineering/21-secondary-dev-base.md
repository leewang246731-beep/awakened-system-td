### 2.2 目录规范与 manifest schema（采纳 R1，适配现状）

```
E:\game-assets\                 # 作者侧源库（U 盘）
  era-banners\                  # 章节题图：{era}-banner-{name}.png（1024²级，16:9）
  characters\                   # 军师人格头像等：system-avatar-{persona}.png（人工重绘）
  scenes\                       # 场景概念/静帧：{era}-scene-{name}.png
  manifest.json                 # 总清单（schema = game-assets/1，采纳 R1 §4.2）
  _licenses\                    # 第三方包许可证快照（与 docs/assets/licenses 双备份）
E:\game-videos\
  raw\                          # AI 母片 mp4：{era}-{subject}-NN.mp4
  dist\                         # 转码成品 .ogv + .check-*.png 抽检帧
```

- **manifest schema 采纳 R1 §4.2 原样**（entry 字段：id/type/era/category/files{raw,dist,sha256}/source{kind,generator,task_id,prompt,generated_at,resolution,duration_s,fps}/transcode{cmd,tool,date}/license/usage{scene,trigger,skippable,fallback_web}），仅两点适配：①category 枚举改为 `{era-banners, characters, scenes, video}`；②video 条目 `files.raw/dist` 指向 `E:\game-videos\`。
- **存量迁移**：三个类目既有文件与 `E:\game-videos` 两个日期命名母片（2026-10-14_awakening-cutscene.mp4 等）不强制改名，首次跑 update_manifest 时全量登记（`renamed_from` 留痕）；新增素材严格 kebab 命名（`{era}-{subject}-{state|variant}.{ext}`，15 号 FILENAME-KEBAB 同规）。
- **R1 era-first 树搁置理由**：现状类目数（3+1）< era 数（6），当前量级扁平类目优先更可读、零搬迁成本；**复议触发条件**：任一类目 >30 文件或 E5/终章素材启动时，按 R1 §4.1 方案迁移并在 manifest 记 `moved_from`。
- 加载器只信 manifest 不信目录枚举（枚举仅校验"声明的文件都存在"，R1 §3.4 要点 1）。

### 2.3 mp4→ogv 转码管线（采纳 R1 §1.2/§4.4）

标准命令（钉死 720p/24fps，防 Seedance 默认帧率漂移）：

```bash
ffmpeg -y -i raw.mp4 -vf "scale=-1:720" -r 24 -q:v 6 -q:a 6 -g:v 64 dist.ogv
```

纪律（全部采纳 R1）：`-q:v 6` 平衡档（高分源可 5）；GOP 64~512 且避开恰过 2 的幂；VBR 优先；先出高码率中间片再二压；ffmpeg 需 libtheora/libvorbis 构建（`-version` configuration 行确认）；**批量转码后逐条目抽 3 帧目检**（Windows 64 位构建偶发 Theora 花屏，r/godot 先例）；不用 Blender 内置 Theora 导出。工具化为 `tools/video/transcode-ogv.sh` + `tools/video/update_manifest.py`（ffprobe 元数据+sha256+manifest 回写），随 T-147 交付；验收口径=dist 无 mp4 残留、manifest 与 dist 1:1、抽检帧目检通过。

**像素化滤镜（R1 §4.5，【单源-派生】）搁置为可选开关**：觉醒系统演出保留全清晰视频（"系统超然于像素世界"的风格反差即表达——采纳 R1 的叙事建议）；仅"游戏内世界"插入画面确有需要时再启用。

**性能铁律（R1 §2.3 采纳）**：视频只在非战斗态出现，战斗内零视频；过场结束立即 `vp.stream = null` 释放；Web 导出视频判死——Web 构建提供"静帧+文字"降级路线（与 D-32/F-164/T-110 的 Web 约束同域，进 T-147 验收）。

### 2.5 加载双轨（采纳 R1 C6/C7/§3.2~§3.4）

1. **开发期（作者侧，U 盘按需加载）**：图片走 `FileAccess.GetFileAsBytes(path)` → `Image.LoadPngFromBuffer(bytes)` → `ImageTexture.CreateFromImage(img)`（生产路径带 Error，`load_from_file` 失败静默弃用）；外部路径 `load()` 一律不可用。视频走 `VideoStreamTheora` 实例 + `.File = "<绝对路径或 user://>"`（`set_file`，无需导入步骤）。统一经 `RuntimeAssetLoader`（R1 §3.2 C# 骨架：缓存字典+ScanPack；大图解码走 `WorkerThreadPool` 后台线程，主线程只做纹理上传）。
2. **发布期（内置 res://）**：定稿素材（人格头像、章节题图、章节过场 ogv）由构建脚本从 E 盘 dist 聚合拷入 `res://`（如 `res://video/{era}-*.ogv`），走导入管线+`ResourceLoader.load_threaded_request`。**同一 manifest 驱动双轨**——发布脚本是 manifest 的第二个消费者。
3. **玩家侧可选扩展包**（DLC 式，预留）：包根 manifest.json + 玩家侧拷至 `user://packs/<pack_id>/` 加载；逐项校验（尺寸白名单 16/32/48/64、调色板数、kebab 命名）复用 asset_validator 同规则（T-046 门禁外延，随 T-146 落地）。
4. 像素一致性：运行时 ImageTexture 不受导入器影响，项目全局 `default_texture_filter=0`（Nearest）对外部加载同样生效（R1 C10），无需额外处理；外部 16×16 图进 32px 世界格沿用 2× 整数放大先例，不预放大。

## 3. 贯穿式彩蛋体系（决策版）——来源 R2（19 号）

### 3.1 采纳原则（三筛选轴）

1. **惊喜度÷成本**：排序值 ≥2.0 优先（R2 §五排序）；两大旗舰载体（系统对话"系统记得你"+遗迹考古"遗迹埋着你"）必须占首批主体——这是本作区别于一切竞品的免费彩蛋资产。
2. **四章基线内落点**：全部触发与回收点落在 E1~E4（Q8 基线）；跨章伏笔回收必须在 E4 内（E-01 唯一跨章件，回收点=E4"另一个声音"登场）。
3. **不碰三不变式**（§11.1 动作封闭/权限分级/预算限量）与 R2 P1~P8 全项：零新增动作（K-4 枚举冻结）、零数值接触、表现层隔离（彩蛋状态只写 profile.db global 域）、关闭系统全装饰可达。

首批规模裁定为 **10 项**：= R2 分章建议（v0.1 批 E-01/02/04/05/08/09 + v1.0 批 E-03/06/10/11）合并去重，剔除依赖首批交付才能成立的计数类件（E-12/E-13/E-16）与纯填充件（E-19）。

## 4. 养料经济（决策版）——来源 R3（20 号）

### 4.1 采纳的最轻方案（R3 方案 B，+C 作可选子件）

**养料 = 开发者出资的、一次性签名兑换码核销的、经极小中转端点路由的 L3 云档体验额度**。五要件：

1. **签名兑换码**：16 字符 Base32（80 bit 熵）；Ed25519 签名域={code_id, amount 1..50, kind daily|task|egg, expiry, pool}；私钥仅存生成机（开发者本地），公钥内置客户端+Worker；**双层验证**=客户端离线验签（防伪即时反馈）→ 服务端 D1 事务核销（真一次性）；本地余额只是显示缓存，权威余额=响应头 `X-Essence-Remaining`。
2. **Cloudflare Worker + D1**（~300~400 行 TS，免费档 ¥0）：`POST /redeem`（验签→原子核销→发设备绑定会话令牌）+ `POST /v1/chat/completions`（验令牌→日限→预算计数→按 pool 路由转发→透传 SSE→注入余额头）；须绑自定义域名；Worker 代码开源入仓可社区自托管（R12 接力）。
3. **免费 Flash 优先路由**：默认 pool=`glm-flash`（GLM-4.5-Flash/GLM-4-Flash 永久免费，常态边际成本≈¥0）；大额码 `glm-paid` 按量 key 池（仅存 Worker Secret；**绝不含 OpenAI key 与 Coding Plan 类订阅 key**）；Q14 智谱问询未获回复前付费池不上线。
4. **日熔断**：全局日预算 cap=¥5（最坏月支出 ≤¥150）+ 80% 告警（¥4 通知开发者）；触发即 Worker 503，客户端回落。
5. **永不硬墙**：三层回落链 system-pool 拒绝（耗尽/熔断/不可达）→ 自动回落玩家 BYOK → 未配置则 L1 语法档；一次性横幅告知（AI Dungeon 硬墙教训）。

**搁置判定**：方案 A（纯静态签名码）**证伪**——"一码一用+计量+熔断"必须有在线组件，无服务端=客户端必持 key=被所有 provider 条款禁止；方案 C（Cloudflare AI Gateway）不单独成案，降为 B 的可选转发子件（省自写计量）；方案 D（LiteLLM 自托管）过重，列为规模化后升级路径。

### 4.2 经济参数（采纳 R3 §3）

| 项 | 规格 |
|---|---|
| 单位 | 1 养料 = 1 次军师 L3 云档对话调用；context ≤16,000 tokens、max_tokens ≤1,024/次（§11.6 守卫复用） |
