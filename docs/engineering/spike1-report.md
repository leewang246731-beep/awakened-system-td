## 1. 结论（W1 出口② 判定）

**判定：PASS——300 敌+1000 弹迷宫复合场景，Tier A 逻辑预算达标（三次运行中位数）。**

| 门禁（Tier A 逻辑层） | 线 | 实测中位 | 裕量 |
|---|---|---|---|
| 均逻辑帧（sim Step + 弹影层） | ≤10 ms（16.6 ms×60%，渲染余量口径） | **1.336 ms** | 7.5× |
| sim tick p99（G8 Tier A 原文） | ≤12 ms | **1.677 ms** | 7.2× |
| 流场帧切片均值（v3.2 §6） | ≤8 ms | **0.0003 ms**（稳态窗） | ~25000× |
| 流场全程单切片最大（含 100 次全图重建） | ≤10 ms（8 ms 预算+批过冲，spike② 先例口径） | **8.08 ms** | 预算机制内 |
| 分桶 | ≤6（G8） | 1（单 lane×costType） | ✓ |

场景完整性（三次运行全部成立，确定性断言）：窗内**活敌最少 330**（均值 333）、**活弹均值 934**（最少 832/最多 1180，目标 1000±25%）、窗内真实射击 78191 发（43.4 发/tick ≈ 87% 塔持续供弹）、百塔全放置全应用、迷宫化路径比 3.27（181 格 vs 直线 55.3 格）。

## 2. 场景构造（128×128 迷宫复合）

| 要素 | 实现 |
|---|---|
| 地图 | 128×128 全平原打底（比例 0/0/0，地形确定性生成），构造后经 `GridWorld.SetTerrain` 公有 API 刻迷宫：贴边 2 格厚环墙 + 六道 Wall 蛇廊柱（x=16/32/48/80/96/112，西三道东三道；顶缺口列 {16,48,96} 缺 y2..9，底缺口列 {32,80,112} 缺 y118..125） |
| 基地 | (64,64) 地图中央=流场目标。敌从 (20..28,106..118) 出生块出发：南穿 x32 底缺 → 北上 x48 顶缺 → 南下抵基地，路径 181 格 vs 直线 55.3 格（比 3.27，从**离基地最近的出生角**起测，不吃远角红利） |
| 波次 | 真 WaveSpawner 公式链（T-036 库，无本地重实现）：threat 2.55 ⇒ 数量乘子 4.25/hp 乘子 3.0/间隔乘子 0.5（60s=1800 tick）；BaseCount 40+ ramps 停摆（BeginWave 99）⇒ 每波 floor(clamp(40)×4.25)=**170**；grace 0.1（压缩至 180 tick，低于 F-034 产品带 1.5~2——压测旋钮，见 §7 坑 6）⇒ w1@t=180、w2@t=1980（测量窗起点的补兵波）、w3@t=3780 恰在 run 外。BatchesPerWave=1：整波 170 只同 tick 入场（spawn 尖峰本身计入负载） |
| 敌种 | 5 种仅速度不同（3/4/5/6/7 px/tick，hp 2600×3.0=7800，经生产 `EnemySpecCatalog.Parse` 严格装载）。速度离散把同波单批沿蛇廊拉开：快组先抵基地形成**到达堆**（永久在场的合法目标），慢组全程在途——窗内在动敌最少 34、窗末到达堆 296 |
| 塔 | 100 座 `spike1:arrow-hedge`（Pierce，reload 2 tick、range 9 格、damage 1、ammo 0——无弹药物流，弹流共存是 spike② 的命题）：全部经**真命令流** `build-tower`（扣费→BuildingRegistry 占用→流场 3×3 脏区）落位，t=200..794 每 6 tick 一座；环形布在基地切比雪夫距离 4..8（北侧留 |x−64|≤6 廊门供敌抵基地），塔-到达堆距离 128..256px < 射程 288px ⇒ 全员持续有目标 |
| 弹（1000 活弹达成法） | **E1 战斗路径是 hitscan**（WeaponFire.TryFire 当 tick 结算，Simulation 无在飞弹实体，快照 Projectiles 恒空）——任务卡"塔数量×射速×lifetime 调参"在 hitscan 下活弹恒为 0。处置：**弹影层**（Spike1Projectile，K-6 IProjectile 契约形态）由塔的**真实开火事件**驱动（FiredCount 增量=50 发/tick=100 塔÷reload 2），每 tick 支付真实弹道层成本（追踪推进+邻近命中判定+寿命剔除，swap-remove），**不二次结算伤害**（sim 已按其战斗路径结算恰一次）。稳态活弹=生成率×平均在飞时长=50×~19≈**934 实测**（命中距离 128..256px÷弹速 9px/tick≈14..28 tick，寿命上限 32 tick） |
| 测量窗 | 预热 1980 tick（初建+百塔落位+首波抵基地）+ **1800 tick（60s@30Hz）稳态窗**；全程 3780 tick |

## 4. 分段剖面（粗粒度外包裹——Simulation 无分段钩子，T-043 卡允许口径）

剖面构成：每 60 tick 对运行中对象做微采样（hash=真 `ComputeStateHash()` 计时；move=twin `UnitMovement.StepAll` 推进同位克隆；target-scan=按 `Simulation.FindTarget` 同算法百塔复算）+ 全程第二个 FlowFieldManager（同世界视图/同 8ms 预算/同脏区事件）逐 tick 计时。

| 段 | 窗内均耗时 | 占 sim 均值（0.959ms）份额 | 口径说明 |
|---|---|---|---|
| 全态哈希 ComputeStateHash | 0.58 ms | ~60% | 真计时（回放不变式的每 tick 成本，含 340 只单位+百塔） |
| 战斗（找目标扫描） | ~0.29 ms | ~30% | 复算口径：百塔全扫 0.61ms，tick 内实际仅 ~50 塔就绪→折半；WeaponFire 计数本身 ~0 |
| 单位移动 | 0.047 ms | ~5% | 克隆推进口径；窗内在动敌最少 34（到达堆停走，StepAll 早退）——**低于 300 全在动场景**，见坑 4 |
| 流场切片 | 0.0003 ms | ~0% | twin 口径（稳态无脏区=双管理器同状态，成本相等） |
| 快照发布+命令+spawn+杂项 | ~0.04 ms（余额） | ~5% | 差额推得（含每 tick 单位视图数组分配） |
| 经济/物流 | ≈0 | 0% | 场景按定义无经济建筑/民夫（供弹链共存属 spike② 命题）——**剖面局限**：本基准不覆盖 Producer/Converter/Carrier 段成本 |

局限声明：twin/复算/克隆均为粗粒度归因仪器（不进逻辑帧门禁计时），绝对值受缓存与采样扰动，份额为量级参考；sim 内部真实各段不可分离（无钩子），余额项含归因误差。

## 6. 与 G8 / 08 W1 出口② 的对照声明

- **Tier A（本 spike 交付物）**：基准场景+断言已进 `dotnet test` 域（G1 内随跑）；13-gates G8 的 perf-budget 独立流水线段可依本报告 §3 中位数挂线（劣化 >20% 即红 ⇒ 红线=中位×1.2，本测试内已先以 ×2.25/×2.4 回归线保守接管）。分桶 ≤6：单场景 1 桶，结构上限由 FlowFieldManager 构造参数（6）保证。
- **Tier B（不在本 spike）**：真机 60s 窗口 P95 ≤16.6ms 且无 >50ms 帧属后续真机档（W5/T-102 渲染三档联动）；CS-4.8：本报告全部数字为 headless 逻辑预算，不宣称 60fps。
- **W1 出口②（02-G4 缺口收口）**：流场性能口径统一为"迷宫+供弹共存场景流场 ≤8ms/帧（Tier A）+整帧 ≤16.6ms（Tier B 真机）"——本报告给出 Tier A 侧的迷宫复合实测与门禁；供弹共存侧数字引用 spike② 留档（同图系双代价走廊、重建 1.66ms≪8ms）。

## 7. 发现的坑（设计输入）

1. **hitscan 无在飞弹——"1000 活弹"必须先立口径**：E1 薄战斗（T-038/T-040）TryFire 即结算，Simulation 弹实体缺位（快照 Projectiles 恒空数组）。本 spike 用"真实开火事件驱动的 IProjectile 影层"度量弹道层每 tick 成本；**后续时代引入真实弹实体（C-09 演进/K-6 落地）时应替换影层重取基准**，届时命中判定/溢出伤害的真实结算成本才会入表。
2. **全态哈希是当前最大逻辑段（~60%）**：回放不变式要求每 tick FNV 全量（340 单位×~12 mix+百塔）。绝对值 0.58ms 远离红线，但它是**随单位数线性增长**的固定税——千单位级场景前需评估"哈希降频（N tick 一哈希+事件计数）"或增量哈希，属 C-12 演进决策点。
3. **塔放置即全图重建，百塔=百次 128² 洪泛（均 7ms/次，单切片≤8.08ms 预算内）**：建造密集期流场占满预算帧。产品化路径：(a) FlowFieldManager coverage 覆盖窗把重建限于受影响列（spike② 坑 7 同结论）；(b) 编排层把连续放置的脏区合批（现有 MarkDirty 合批已支持，缺的是命令侧合批时机）。
4. **到达堆语义影响剖面代表性**：稳态窗 89% 活敌为"到达停走"状态（296/330），移动段成本被压低（在动最少 34，二波持续补走在途敌）。若产品场景是"300 全在动"，移动段约放大至 0.047×(300/均值在动)——按最保守 300/34≈8.8× 也就 0.4ms，不改变达标结论，但**重取基准时应记录在动数**。
5. **单帧最大含 GC/调度尖峰**（留档曾见弹影层 31.9ms 单次）：Tier A 门禁因此锚中位数/p99（T-037 先例），单帧最大仅留档；>50ms 帧的否决权在 Tier B 真机档。弹影层 List 增删每 tick ~50 次分配——产品化用对象池/结构数组可消。
6. **压测旋钮偏离产品带，均已在 §2 注明**：grace 0.1（<F-034 带 1.5~2，为把两波塞进有界 harness）；敌速 3~7 px/tick（>E1 带 1.6~2.56，为压缩抵达时间——每 tick 成本与速度无关）；damage 1/hp 7800（击杀率≈0 以守住 300 在场基数）。三者皆场景参数而非引擎行为变更。
7. **迷宫比从最易出生角起测**（3.27）：避免选远角虚增；若后续调出生块，此断言先红。
