## 1. 架构候选评估与细化（EraCore）

### 1.1 候选对比

| 候选 | 描述 | 裁定 | 理由 |
|---|---|---|---|
| A. 单 Godot C# 项目（程序集内分层） | 全部逻辑写进 Godot csproj，靠命名空间分层 | **否决** | 任何测试都要拉起 Godot 运行时，单元测试慢一个数量级；无法满足"每个开发点都有真实覆盖的单元测试"这一硬要求；多代理并行合并冲突面大 |
| B. EraCore 纯 C# 库 + Godot 引用 | 逻辑库零 Godot 依赖，xUnit 直接 `dotnet test` | **采纳（细化如下）** | 仿真/公式/智能体管线/语法/持久化全部可纯测；Godot 层薄，回归风险集中 |
| C. 多程序集 EraCore.Sim / EraCore.Agent / EraCore.Content | 按 domain 拆 csproj | 备选（暂缓） | 合并冲突收益在 31 组件规模下有限，解决方案复杂度先行；若泳道间 git 冲突频发再拆（拆分点已在命名空间上预留：`EraCore.Sim.*` / `EraCore.Agent.*` / `EraCore.Content.*` / `EraCore.Meta.*`） |

### 1.2 细化：端口-适配器三层

```
┌─────────────────────────────────────────────────────────┐
│ game/ui/*.gdscript          GDScript 仅 UI（面板/按钮/轮盘）│  ← 层 3：表现
│ game/scenes/*, game/adapters/*   Godot C# 场景与端口适配器   │
├─────────────────────────────────────────────────────────┤
│ game/src/EraCore/           纯 C#，net8.0，零 Godot 引用    │  ← 层 2：逻辑
│   Sim.* Agent.* Content.* Meta.* Ports.* Foundation.*     │
├─────────────────────────────────────────────────────────┤
│ game/src/EraCore.Tests/     xUnit + 金样 + 回放 harness     │  ← 测试（dotnet test，不启动 Godot）
└─────────────────────────────────────────────────────────┘
```

1. **端口（Ports，EraCore 内定义接口，Godot 侧实现）**：

| 端口 | 职责 | Godot 实现 | 测试 Fake |
|---|---|---|---|
| `IClock` / `IRng` | 时间与随机（**禁止** `DateTime.Now`/全局 `Random` 进 EraCore，保证确定性） | 系统时钟桥 / PCG64 播种桥 | 固定序列 Fake |
| `IFileStore` | user:// 抽象读写 | `Godot.FileAccess` | 内存 FS |
| `IPersistPort` | 存档后端切换 | 桌面=SQLite（Microsoft.Data.Sqlite，库随游戏目录）；Web=JSON 文件（见 §7 R-E2） | 内存/临时目录 |
| `IHttpPort` | SSE 流式 HTTP（请求→增量回调→完成/错误） | `HTTPClient` 轮询 + Thread + `call_deferred` 回主线程（§11.7） | 预录 SSE 字节流 |
| `ISecretStore` | Key 存取 | Windows DPAPI（`ProtectedData`）/ 回落 user:// 文件 0600 | 内存 |
| `IJobPort` | 后台作业（流场重算等） | WorkerThread / Web 单线程时退化为分帧切片 | 同步直跑 |

2. **确定性原则**：模拟固定 30 Hz tick + 命令队列（`SimCommand`）+ 播种 RNG；"回放 = 同 seed + 同命令流 → 同状态哈希"，战报 JSONL 与事件总线同源（§10.6 回放功能直接复用）。
3. **快照原则**：EraCore 每帧输出不可变 `SimSnapshot`（双缓冲），Godot 只读渲染（MultiMesh 脏标记更新）；反向只经 `SimCommand` 进入，杜绝表现层写状态。
4. **守卫测试（架构红线）**：xUnit 反射断言 `EraCore.dll` 的引用集不含 `GodotSharp`——多 AI 代理并行时防"图省事引用 Godot 类型"的边界腐蚀；此测试属于 C-01 并入 CI 必跑。
5. **工程布局**（全部在 D 盘）：
   - `D:\game\game\project.godot`（Godot 项目根）；`D:\game\game\src\EraCore\`、`D:\game\game\src\EraCore.Tests\`（`dotnet test` 直跑）；
   - 环境约定（写入 C-30 的开发文档）：`DOTNET_ROOT=D:\dotnet`、`NUGET_PACKAGES=D:\nuget`、`GODOT_BIN=D:\game\tools\godot\Godot.exe`；CI 上同构（GitHub Actions Windows runner + 便携 Godot + NuGet 缓存）。
6. **裁定**：候选 B 细化后成立，且是满足"测试极严"约束的唯一低成本路径；候选 C 保留为冲突触发式演进。

## 4. 测试策略映射

总原则（对齐"每个开发点都要有真实覆盖"）：**Layer 0~4 的组件 100% 测试跑在 `dotnet test`（不启动 Godot）**；Godot 层组件跑 headless 集成；每类组件按下表组合四层测试（单元/逻辑/集成/回归）+链路（E2E）。测试与实现同任务交付，code-review 的 Spec 轴把"测试是否真实覆盖"列为否决项。

| 组件类型 | 单元/逻辑（xUnit，dotnet test） | 集成 | 回归 | 链路（E2E） |
|---|---|---|---|---|
| 纯逻辑库（C-01~C-20, C-29） | 公式性质测试（守卫/clamp/除零/边界，如伤害下界 10%、效率 min(供给率)）；表驱动规则测试（信任度/权限矩阵） | 组件组合测试（如 C-06+C-07+C-11 迷宫供弹共存），仍在 EraCore.Tests 内、秒级 | **确定性回放**：同 seed+命令流→状态哈希相等；**JSON 金样**：方案卡/波次构成/存档规范化输出比对 | headless 命令脚本打完整关卡→断言战报 JSONL 与存档 |
| Godot 场景（C-21~C-26） | 不适用（该层禁业务逻辑，逻辑全部下沉） | **gdUnit4Net**（Godot 官方生态 C# 测试框架，VSTest 兼容、`dotnet test` 经 GODOT_BIN 拉起 headless Godot，适配 CI）；场景加载+状态注入→节点树断言 | 缩放整数性/像素对齐断言；"关闭系统降级路径"回归（R2） | 与 C-30 端到端用例共用 |
| 数据/资产（C-02, C-28, C-29） | schema 校验器单元（合法/非法/恶意 JSON 矩阵） | 全量内容加载冒烟 | 金样哈希（schema→规范化 JSON）；**许可证审计脚本**（新素材必须带 license 记录否则 CI 红）；调色板 ≤64 色校验 | — |
| 工具/测试（C-30, C-31） | 元测试（守卫测试自身有效） | CI 冒烟 | 导出产物结构断言（zip 内容清单）；Web 导出 threads-off 配置检查 | headless 导出冒烟 |
| GDExtension（C-27，远期） | 假后端单元 | 降级链路（L2 失败→L1）回归 | 真模型 optional-skip | — |

**MiMo（L3）集成测试的 optional-skip 方案**：

1. 标记：自定义 `[LlmIntegrationFact]`（继承 xUnit `FactAttribute`，构造器内判定）+ `[Trait("Category","Integration:Llm")]`；无 Key 时 `Skip="BYOK key 未配置（config/secrets.local.json 或环境变量 ERA_TEST_LLM_KEY），跳过真实 MiMo 调用"`，测试仍可见、显式跳过而非消失。
2. Key 来源（密钥纪律）：`config/secrets.local.json`（已 gitignore）或环境变量 `ERA_TEST_LLM_KEY`；端点 `https://api.xiaomimimo.com/v1`、模型 `mimo-v2.6-pro`（方案 §11.6 实测条目）。CI 默认无 Key=全跳过；手动流水线（监督人本机）注入后运行。
3. 断言口径：**只锁结构不锁内容**——响应必须通过 C-03 Schema 校验（合法动作 JSON）、双超时/重试/错误分类协议机行为正确；不做字面输出比对（LLM 输出不定）。
4. Cassette 回放：真实调用一次即录 JSONL（请求摘要+SSE 事件序列，**剥离 Key**），入库为测试夹具；离线回归用 cassette 驱动 `IHttpPort` Fake，覆盖协议机全部分支（半行拼接、`[DONE]`、reasoning_content、429 重试、1315 文案）。
