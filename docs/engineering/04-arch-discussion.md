## 1. 对 03"端口-适配器三层"的评审

### 1.1 总体裁定：同意

EraCore 纯 C# 零 Godot 依赖 + Godot 表现层 + 数据层的三层结构成立，理由与 03 一致且我要加重三点：

1. **它是"测试极严"约束下唯一可行的低成本路径**。177 特性中约 110 项（A/B/C/E/F/G/H 组大半）是纯逻辑/数据，xUnit 秒级回归只有零 Godot 引用时才可能；候选 A 会让 CI 时间从分钟级劣化到小时级。
2. **确定性是本项目的隐藏刚需**。方案隐含三处依赖确定性：JSONL 战报回放（F-121/F-174）、两级存档映射 spike（F-168）、无尽三榜成绩可信（F-123）。30 Hz 固定 tick + `SimCommand` 队列 + 播种 RNG + 快照双缓冲（03 §1.2 条 2/3）是正确底座，我完全支持并建议把"回放=同 seed+同命令流→同状态哈希"写成 EraCore 的**架构级守卫测试**（不止是测试手段，是产品承诺）。
3. **反射守卫测试（§1.2-4）保留**，且加一条：EraCore 内**禁止 `System.Reflection.Emit`、禁止 Newtonsoft、禁止 `System.Net.Http` 直连**（理由见 §3.4/§3.5——Web AOT 导出）。

### 1.2 修改一：solution/project 布局（与 03 的实际分歧）

03 把 `project.godot` 放在 `D:\game\game\` 根、`src/` 与运行时数据混在其下。**我反对这个布局，建议 Godot 项目根独立成子目录**，因为：Godot 会把项目根下一切文件当 `res://` 导入（`saves/*.db`、`reports/*.jsonl`、`mods/` 全部进导入扫描与导出清单）；且 res:// 在安装后是只读目录的惯例会被"游戏目录可写"假设打破。

```
D:\game\game\                          ← 代码根（git 仓库内）
├─ AwakeningTD.sln
├─ Directory.Build.props               # TFM=net8.0、Nullable、Analyzers、版本集中管理
├─ src\
│  ├─ EraCore\                         # 纯逻辑库（唯一被守卫测试盯防的程序集）
│  │  ├─ Foundation\                   # 领域原语、IClock/IRng、事件总线
│  │  ├─ Ports\                        # IFileStore/IPersistPort/IHttpTransport/ISecretStore/IJobPort
│  │  ├─ Sim\  Agent\  Content\  Meta\ # 03 候选 C 预留的拆分点（命名空间即未来 csproj 边界）
│  │  └─ EraCore.csproj                # net8.0，零 GodotSharp 引用
│  └─ EraCore.Tests\                   # xUnit + 金样/回放/cassette（dotnet test，不启动 Godot）
├─ presentation\                       # Godot 项目根（唯一 res://）
│  ├─ project.godot + Game.csproj      # csproj 引用 ..\src\EraCore
│  ├─ scenes\  adapters\  ui\          # C# 适配器 + GDScript UI
│  ├─ assets\  content\                # content 由 E 泳道产出，构建期同步入 res://
│  └─ .godot\                          # 导入缓存（CI 可缓存）
├─ contracts\                          # K-1~K-12 冻结契约 + JSON Schema（评审产物，03 §6 纪律）
├─ data\
│  ├─ saves\                           # SQLite + 滚动备份（gitignored；含 .gdignore 防误导入）
│  └─ reports\                         # JSONL 战报（运行时产物）
├─ mods\                               # 外部模组挂载点（F-165）
└─ tools\                              # CI/导出/许可证审计脚本
```

**代价**：导出预设与 CI 路径多一层目录；03 的 C-21/C-30 任务卡需按此树改写。**收益**：运行时可写目录永不进 res://；contracts 可被 code-review 直接 diff；未来候选 C 拆 csproj 时 `src/` 平移即可。

### 1.3 目标框架：net8.0（同意 03，补充 EOL 事实）

我建议全解决方案统一 **net8.0**（`Directory.Build.props` 一处钉死），因为 Godot 4.7.2 mono 构建内置 .NET 8 运行时、本机 SDK=8.0.425、C# Web AOT 导出工具链按 .NET 8 校准——TFM 高于内置运行时直接无法加载。

必须记录的事实：**.NET 8 LTS 支持止于 2026-11-10（距今约 4 周）**。我的裁定是不为此迁移：游戏离线分发、自带运行时（self-contained），框架 EOL 的安全面影响接近于零；代价是"官方不再打补丁"，若 v0.5（Web 导出落地时）Godot 模板转向 .NET 10，则一行 props 切 `net10.0` 全量回归——把它列为 v0.5 里程碑的检查项而非现在的动作。**禁止** EraCore 用 `netstandard2.x` 来"保持灵活"：会失去 System.Text.Json source-gen 与 Span 一致性，且并不解决任何实际问题。

### 1.4 Godot 版本策略：固定 4.7.2-stable mono（03 未钉死，这是缺口）

03 只写"Godot 4"。我建议**固定 4.7.2-stable mono 精确补丁号**，理由：

- **不能用 4.3**：C# Web 导出（NativeAOT 实验特性）4.4 才落地，v0.5 的 HTML5 Demo（F-144）在 4.3 下是死路；4.3 的 .NET 支持也早一个时代。
- **不追最新 stable**：mono 编辑器、mono 导出模板、GodotSharp、gdUnit4Net 四者必须版本对齐，浮动的"最新"会让 R-E1（headless 测试）变成持续风险。
- **升级策略**：仅在里程碑边界（v0.1/v0.5）评估升级，一次升一档补丁版，全量回归后钉死；导出模板版本必须与编辑器**精确匹配**（版本号不同的模板会被 Godot 拒用）。

**D 盘纪律补漏**（03 漏了一处）：Godot 导出模板默认装到 `C:\Users\…\AppData\Roaming\Godot\export_templates`，违反"只在 D 盘"。C-31 首个任务 = 编辑器设置里把 Export Templates Path 改到 `D:\game\tools\godot-templates\`，并写入开发文档。同理 **`user://` 默认也在 C 盘 AppData**（见 §2.2）。

### 1.5 AOT 红线（03 未写明，Web 导出的硬前置）

C# Web 导出=NativeAOT+裁剪，反射即死。Day-0 起强制三条：①EraCore 序列化只用 **System.Text.Json source generator**（`JsonSerializerContext`），禁反射序列化；②禁 `Reflection.Emit`/`Assembly.Load`；③所有第三方库入库前查 trim/AOT 兼容性。**代价**：每个 DTO 多一个 `[JsonSerializable]` 标注与上下文类，约半天的全项目一次性习惯成本；**收益**：v0.5 Web 导出不返工。

## 2. 数据与持久化裁定

### 2.1 三类数据分流（回答"JSON 文件 vs SQLite"）

| 数据 | 裁定 | 理由 | 代价 |
|---|---|---|---|
| 内容注册表（塔/敌/波次/时代/科技/卷轴/台词） | **JSON 文件 + schema 校验 + manifest 哈希清单** | 模组（F-165）=玩家丢文件进目录，必须保持"文件即内容"；git 可 diff、无迁移负担；运行时只读 | 加载期全量校验耗时（千级条目 <100ms，可接受）；校验器要自研薄层（§3.4） |
| 存档（全局 profile + 关卡 chunk） | **SQLite（Microsoft.Data.Sqlite 8.x，e_sqlite3 随游戏目录，不装服务）** | 满足"嵌入式、只在 D 盘"；时代跃迁事务（30% 课税+遗迹生成）需要跨全局/关卡的**单事务原子性**，文件方案要自己造；损坏恢复有 WAL 日志兜底 | 导出包必须确认 e_sqlite3 原生库进 zip（03 R-E5 已列）；Web 版需 JSON 等价后端（见下） |
| 系统战报（JSONL） | **追加式 JSONL 文件，不进 DB** | 战报的消费者是回放工具（F-174）与人（debug）；行级追加天然抗崩溃；与事件总线同源编码可直接 diff | 需自做轮转（建议保留最近 50 局 / 200MB 上限，可设置） |

我同意 03 的 `IPersistPort` 双实现（桌面 SQLite / Web JSON 回退），但要求**同一测试套件参数化跑双后端**（03 R-E2 已有，保留为验收项）。

### 2.2 "只在 D 盘"的落实（03 的隐性违约点）

`user://`（IFileStore 的默认映射目标）在 Windows 上是 `%APPDATA%\Godot\app_userdata\…`——**C 盘**。裁定：`IFileStore` 的根目录由 Godot 适配器**注入**，不使用 user:// 默认值：

- 开发机：`D:\game\game\data\`（saves/reports 其下）；
- 发布包：可执行文件旁 `saves\`（便携式 zip 分发天然成立）；写入失败（如用户放进受保护目录）时弹窗引导指定目录；
- Web：浏览器持久化 FS，仅 JSON 模式。

代价：放弃"多游戏共享 Godot 用户目录"的惯例（本项目无此需求）；收益：D 盘纪律真实成立而非纸面成立。

### 2.3 两级存档格式细节（meta+chunk 版本化，对 K-7 的具体化建议）

1. **单库双域**：`saves\profile.db` 一 个 SQLite 文件，表分两族——`global`（科技/全局资源池/信任度/签到/文明基金/解锁与成就）与 `level_slot(level_id, slot, fmt_version, created_at, payload, seed, cmd_offset)`（每关每槽一行 chunk）。跃迁事务=单 `BEGIN IMMEDIATE` 提交，天然原子。
2. **版本化与迁移**：每行携带 `fmt_version`；迁移器只允许链式 vN→vN+1，代码内注册、每步单测（金样：每个历史版本的存档样本→迁移→断言）。**读到比代码更新的版本 = 拒载 + 自动备份原库**，绝不半载。
3. **原子写**：SQLite `journal_mode=WAL` + `synchronous=FULL`；库级更换走 temp+rename；每槽保留**最近 2 个版本 payload**（滚动备份列），坏档可回退一代——这直接服务 F-004"只清本关存档"与 F-057"冲突降级不丢档"。
4. **存档内容形态 = 波界快照 + 命令尾（混合）**：每波结束落一个全量 `SimSnapshot`（含 seed 与命令日志偏移），波内崩溃恢复 = 快照 + 重放其后 `SimCommand` 尾。理由：与回放 harness **同一条代码路径**（同 seed+同命令流），存档正确性测试免费获得；且波界天然是设计要求的检查点粒度（F-004 第 15 波检查点=A7/N7 裁定后的 ⌊胜波×0.75⌋）。代价：读档延迟=解快照+重放命令尾（≤1 波命令量，毫秒级）；快照体积需压缩（建议 Brotli/gzip 后入库为 BLOB）。

## 3. 关键技术选型讨论

### 3.1 测试框架：xUnit 主力 + gdUnit4Net（有条件）——同意 03 组合，加强一个动作

- **xUnit**（EraCore.Tests）：同意，无异议。理论/性质测试（守卫/clamp/边界）+ 表驱动 + 金样 + 回放 harness 全在此层。
- **gdUnit4Net**：**有条件同意**。必须指出：它是 MikeSchulze 的**第三方**项目（03 称"Godot 官方生态"不准确），v5 官方 README 的兼容性只验证到 **Godot 4.4 / .NET 8-9**，对 4.7 无声明。它经 GODOT_BIN 拉起 headless Godot 跑 VSTest，耦合面主要是 GodotSharp 版本，大概率可用，但**必须 Day-0 冒烟**：C-30 的首个交付 = 在固定 4.7.2 上跑通一个 `[RequireGodotRuntime]` 样例测试。若失败，03 已备的自研最简 runner（headless SceneTree 脚本+退出码）**升级为一等方案**而非兜底——我甚至倾向把 Godot 层测试占比压到 <15%，使这个选择的风险总敞口很小。
- **MiMo（L3）集成测试**：同意 03 §4 的 optional-skip+cassette+只锁结构方案，补一点：真实网络调用只应存在于**测试程序集里的 HttpClient 版 IHttpTransport**（EraCore 保持零网络依赖）；cassette 录制时剥离 Key（03 已写）且**录制文件入 git 前过 Key 泄漏扫描**（RL5 的 CI 钩子）。

### 3.2 流场线程模型：同意 `IPathSolver` 双后端，补三条硬规则

03 的双后端（桌面整帧 burst / Web 分帧切片）方向正确。我补充：

1. **求解器输入必须是不可变 `GridSnapshot`（带版本号）**，工作线程绝不读活体模拟状态——这是 R-E3"重算线程与 tick 数据竞争"的根治法，而不是缓解法。
2. **确定性合并**：分桶按索引固定顺序求解；结果在**tick 边界**原子换入（双缓冲 swap），线程中途不产生可见中间态。
3. **等价性性质测试**：N 张随机迷宫图上 `burst(图) == sliced(图)` 逐格哈希相等，入 CI 必跑；分帧后端的每帧预算来自 `IJobPort`，超支计数器暴露给性能浮层（满足 RL2"可用计数器采样"）。

**代价**：GridSnapshot 化使 C-11 接口多一层间接；**收益**：线程模型可证明而非"跑起来没崩"。

### 3.3 事件总线：同意"JSONL 同源"，但必须钉死为**同步单线程分发**

03 把事件总线放在 C-01 但未写并发语义。我建议：**进程内同步、有序、单线程分发**（tick 内按触发序派发，事件带 `(tick, seq)` 序号），JSONL 编码器只是众多 `IEventSink` 之一（观察者），音频/UI 在 Godot 适配器侧用 `call_deferred` 接力到主线程。**明确反对**任何"异步事件总线/后台线程发布"的通用件：它会在无声中破坏确定性回放（事件跨 tick 重排=回放哈希漂移），而确定性是 §1.1 所述的产品承诺。代价：极端 tick 内事件洪峰会拉长帧（用事件计数监控+合批缓解）；收益：回放/战报/演出/音频四消费者（K-8/K-12）共享同一确定性序。

### 3.4 JSON Schema 校验器：建议 JsonSchema.Net，而非 NJsonSchema

03 未定名。我建议 **JsonSchema.Net**（MIT，活跃维护，完整 draft 2020-12，以 System.Text.Json 为底、无 Newtonsoft 依赖），备选 NJsonSchema v11（成熟但维护放缓、默认绑 Newtonsoft）。决定性理由是 §1.5 的 AOT 红线：Newtonsoft 在 NativeAOT/裁剪下是知名雷区，EraCore 引它会让 v0.5 Web 导出返工。

配套两条：①**行级报错**由两层合成——System.Text.Json 解析期 `JsonException` 自带行/列（语法错），schema 校验错返回属性路径，再映射回最近 token 位置（F-165"错误 JSON 给出行级报错"的落地方式）；②**单一 schema 源双投影**：19 动作与 ContentType 的 schema 手写为 2020-12 子集（避开 OpenAI tools 不支持的关键字），经"schema 编译器"同时产出内部校验用 schema 与 L3 function calling 的 tools JSON——消除游戏侧校验与 LLM 侧声明的漂移（K-3 的隐藏需求）。代价：手写 schema 约束纪律 + 编译器 2~3 天；收益：模组报错可定位、BYOK 参数空间永不与游戏校验分叉。

### 3.5 LLM 网关：同意抽象，命名与实现分层需澄清

同意"网关可整体禁用+域名白名单+模组无网络"（F-162）与 03 的 C-16 边界。两点澄清：①EraCore 侧接口建议名 `IHttpTransport`（请求→SSE 增量回调→完成/错误），**不叫 IHttpClient**——避免与 Godot `HTTPClient`/`System.Net.Http.HttpClient` 两个既有概念混淆；②Godot 适配器按方案 §11.7 用 `HTTPClient` 轮询 + Thread + `call_deferred`（导出的桌面版可用），纯 `dotnet test` 的 MiMo 集成测试用测试程序集内的 HttpClient 实现（§3.1）。cassette 必须覆盖：半行跨块、`data:` 前缀、`[DONE]`、`delta.reasoning_content`、429/1302/1305/401/400/1315/Unsupported-model 全矩阵（03 已列，保留）。
