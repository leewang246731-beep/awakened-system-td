## 0. 结论速览

- **开发顺序**：竖切优先定里程碑形状 + 分层优先定波内秩序（两轴正交，非二选一）。预制作竖切目标 = E1 第 1 关全链路可玩（真流场，禁 mock）。
- **波次**：**Wave 0~7 共 8 个排期波次**（+1 个远期不排期窗口 v1.x+），逐波映射 §18 的 预制作→v0.1→v0.5→v1.0。
- **关键路径**：C-01→C-05→C-11→C-10→C-12→C-13→C-22；且为**双链平台期**（β 链 C-05→C-06→C-07→C-12 等长并行），在 C-12 汇合。v1.0 尾段 C-19→C-20 与 C-13→C-22 等长，两段都要盯。
- **规格冻结**：T-000 系列 15 项（T-000 恢复 git 基线 → T-014 Q8 签认）全部列为 Wave 0 任务；其中 11 项必须在 Wave 0 关闭。
- **总工期**：名义 **40~41 周（约 9~9.5 月）**；加 20~30% 风险缓冲 → **11~13 个月至 v1.0**，与 §18 的 9.5~12 月区间吻合。预制作吃满 §18 上限 8 周、零缓冲，是最紧的一段。
- **与 03 的最大分歧**：D 泳道（Godot 表现）进场时机——03 按"分层并行、集成后置"让 D 在 mock 快照就绪后进场、L5~L6 才联调；本意见书要求 D 从 Wave 1 即以 mock 快照进场、Wave 2 交付真实可玩 UI（30 人试玩门槛所迫），A 泳道 A1/A2 拆分也从"L2 起"提前到 Wave 1 第 1 天。

## 1. 开发顺序哲学：竖切优先 vs 分层优先

### 1.1 两种路线的真实分歧点

| 维度 | 纯竖切（先跑通 E1 一关全链路） | 纯分层（先建 EraCore 全部模型再上表现） |
|---|---|---|
| 首个可玩版本 | 预制作末（第 6~8 周） | Layer 6 完成后（约第 5~6 月） |
| 集成风险暴露 | 第一月即暴露（快照/命令/协议/渲染链） | 最后暴露，返工半径最大 |
| 架构质量 | 易滑向"演示用一次性代码" | 契约充分沉淀，边界干净 |
| §18 预制作验收（≥30 人试玩 ≥7/10） | **可满足** | **不可满足**（无 build 可试玩） |
| spike④ 系统 3 动作闭环 | 顺带产出 | 需临时搭脚手架，事后拆 |
| 数值调参（波次验算/供需基准） | 全链路闭环即可调 | 只有孤立的公式单测，调不了节奏 |

### 1.2 本意见书立场：两轴正交——"波次竖切、组件分层"

**里程碑按竖切组织，波内秩序按分层执行**：

1. **竖切定形状**：每个波次的出口是一个可玩/可验收的切片（预制作 = E1 第 1 关全链路；v0.1 = E1+E2 完整）。理由按权重排序：
   - **风险排序**：02-audit Top-3（R-E1 headless 测试、R-E2 Web 导出、R-E3 流场性能）全部是**集成/性能风险**，只有竖切能在早期暴露；分层优先恰恰把最大风险压到最后。
   - **验收排序**：§18 预制作五项验收（60fps 门禁/迷宫共存/3 动作闭环/30 人试玩/200 条语料）没有一项能靠分层满足。
   - **卖点排序**：觉醒系统是本作差异化所在，spike④"军令→方案卡→塔列队开建"必须最早证伪——它是"系统真的会执行"这一支柱的最小证明。
   - **单人+AI 代理开发排序**：可玩反馈是数值调参（F-171 波次验算）与动力维持的前提；§18 自己就把"E1 竖切"写进了预制作交付。
2. **分层定秩序**：波内组件仍按 03 的 7 层依赖图调度（Layer 0 契约先行、同层并行、跨层串行）。竖切**不豁免架构红线**：
   - 切片必须沿端口-适配器三层走（EraCore 零 GodotSharp，守卫测试在 CI）；
   - **薄 ≠ 假**：RL2 明令流场不得 mock——E1 竖切必须含真流场（这正是它有资格验证 8ms/帧预算的原因）；塔/敌/面板可以是"薄版"（E1 数值子集、占位美术），但实现路径与全量版同一条（同一注册表、同一 Schema）；
   - 薄版组件按"全量的第一段任务"排进任务卡，竖切结束后在后续波次补全，**不产生弃码**。

### 1.3 与 6 泳道的配合方式

- **泳道分两类**：
  - **切片泳道 A/B/C/D**：按波次出口对齐，波次关口做联合验收（不再各自跑到 Layer 顶才碰头）；
  - **常驻服务泳道 E/F**：跨波次连续作业（E=美术管线与内容包、F=CI/测试/发布），按各波需求单排程，不被切片节奏绑架。
- **A 泳道拆分提前**：03 建议"L2 起拆 A1/A2"；因关键路径是 α/β 双链（§4.2），**A1（世界+经济+物流，β 链）/A2（寻路+单位+塔，α 链）从 Wave 1 第 1 天就分拆**，C-12 由 A1 收口。
- **D 泳道提前进场**（本意见书与 03 的主要分歧）：C-21 在 Wave 1 即以 mock 快照开工（03 亦允许），但 C-22/C-23 的**薄版必须在 Wave 2 落地为真实 UI**——30 人试玩门槛不允许"mock 面板"。
- **B 泳道前置**：C-03（动作注册表）在 Wave 0 即出 Schema（K-3），C-14/C-15 在 Wave 2 支撑 spike④；C-16（LlmGateway/L3）排在 Wave 3，可滑至 Wave 4 而不阻塞 v0.1 门槛（v0.1 验收只锁 L1 首解率）。
- **C 泳道热身路径**：Wave 1~2 承担 C-04（存档）+ spike③（遗迹映射原型），正好为新代理提供低耦合热身（03 原建议成立）；但 Wave 3 起接 C-19/C-20（v1.0 关键路径尾段），须换强代理。
- **泳道间唯一交互面 = 12 契约**：波次关口加一道"契约漂移检查"（契约文件 diff 为零或已走变更评审）。
